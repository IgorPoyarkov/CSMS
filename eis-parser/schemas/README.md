# XSD-схемы ЕИС 44-ФЗ (Альбом ТФФ 17.0, итерация 2)

В `Schemas44/` распакован официальный комплект из архива
`Схемы 17.0 итерация 2.zip`: **32 XSD + 16 WSDL**, вложенные каталоги
(`GetDocsWS/…`, `QueueVBS/…`, `WSDL/…`) сохранены. Это машиночитаемая часть
Альбома ТФФ; текстовые описания форматов лежат в 19 `.docx` внутри
`Альбом ТФФ 17.0.zip` в корне репозитория.

## Известная опечатка в исходном архиве

В `GetDocsWS/GetDocsLegalEntity/getDocsLE-ws-api.xsd` после XML-декларации
стоял лишний символ `>` (`?>>`). Схема не загружалась ни парсером, ни
генератором моделей. В распакованной копии опечатка исправлена; исходный
архив не менялся.

## Каталог всех типов

- `TYPE_CATALOG.json` — полные записи: **3548** глобальных определений
  (`complexType` 1674, `simpleType` 690, `element` 1177, `group` 3,
  `attributeGroup` 4), с namespace, файлом, описанием и списком значений
  перечислений.
- `TYPE_CATALOG.md` — та же информация в виде таблиц для чтения.

Пересоздание после обновления схем:

```powershell
./generate-type-catalog.ps1
```

Базовые обозначения форматов из Приложения 1 к Альбому ТФФ: `T` — текст,
`N` — число, `D` — дата `yyyy-MM-dd`, `DT` — дата-время `yyyy-MM-ddThh:mm:ssZ`,
`B` — логический (`1/0`, `true/false`), `S` — составной элемент. Признак
обязательности: `О` — обязательный, `Н` — необязательный.

## Генерация C#-моделей

```powershell
dotnet tool install --global dotnet-xscgen   # если ещё не установлен
./generate-models.ps1                        # запуск из папки schemas
```

Результат — 32 файла в `../src/Eis44Parser.Core/Models/Generated/`
(примерно 29,8 МБ, пространства имён с префиксом `Eis17`). Каталог
исключён из git через `.gitignore`: модели легко воспроизвести, а тянуть
десятки мегабайт сгенерированного кода в каждую сборку не нужно.
Проверено: `dotnet build Eis44Parser.sln` — 0 ошибок, 0 предупреждений.

Сгенерированные классы изолированы в отдельном пространстве имён с привязкой
к версии Альбома форматов. Бизнес-логика и DTO фронтенда не зависят от них
напрямую: связь идёт только через слой мапперов.

## SOAP-контракт getDocsIP

По `GetDocsWS/GetDocsIndividualPerson/WSDL/WebServiceGetDocsIP.wsdl` и
`getDocsIP-ws-api.xsd`:

- Namespace конверта: `http://schemas.xmlsoap.org/soap/envelope/` (SOAP 1.1);
- Namespace тела: `http://zakupki.gov.ru/fz44/get-docs-ip/ws`;
- дочерние теги (`index`, `selectionParams`, …) не квалифицированы —
  в схеме стоит `elementFormDefault="unqualified"`.

Эти значения зафиксированы в `SoapRequestBuilder` и покрыты юнит-тестами.
