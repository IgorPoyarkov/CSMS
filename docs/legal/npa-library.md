# Библиотека НПА проекта

Экран `/legal/library` показывает все нормативные акты, которые использует
проект, и открывает их в том же просмотре, что и цитаты консультанта по 44-ФЗ:
оглавление по всем уровням структуры, переходы по внутренним и внешним ссылкам,
скачивание Word.

## Источники каталога

| Файл | Роль |
| --- | --- |
| `scripts/consultant/pravo-catalog.json` | список всех актов проекта (92) |
| `scripts/consultant/pravo-sources.json` | карточки pravo.gov.ru с хэшами и датами редакций |
| `.tmp/pravo-downloads/downloaded.json` | реестр скачанных текстов (93 записи: 86 актуальных, 7 архивных) |
| `.tmp/consultant/index.json` | число фрагментов каждого акта в поисковом индексе |

Результат сборки — `public/npa-library.json`. По состоянию на 26.11.2026:
92 акта, 86 с локальным текстом, 6 без официальной карточки, 29 519 фрагментов
в индексе. В списке показано полное официальное название акта: вид, дата, номер и
предмет регулирования из шапки загруженной копии. Для отсканированных приказов,
где шапка испорчена OCR, показывается официальное обозначение из карточки —
выдуманные названия не добавляются.

Список содержит по одной карточке на акт. Все загруженные редакции доступны
внутри просмотра: в шапке документа есть список «Редакция» с датами и
признаками «действующая / архивная». По умолчанию открывается текущая редакция;
архивные редакции в ответы консультанта не попадают без явной просьбы о прошлом
состоянии нормы.

## Типовые условия контрактов

Часть 11 статьи 34 44-ФЗ позволяет Правительству РФ устанавливать типовые
условия контрактов, подлежащие применению заказчиками. Такие акты работают
всегда, поэтому они помечаются бейджами «Принято Правительством РФ» и
«Применяется всегда» прямо в общих карточках справочника. Отдельный фильтр
`terms=all|standard|government` в URL позволяет показать только такие акты;
карточки, группы и сортировка у них те же, что у остальных документов.
Акт, который уже есть в статическом каталоге (ПП РФ № 1466), не дублируется:
к существующей карточке добавляются только бейджи.

Данные о типовых условиях приходят из csms-api:

| Компонент | Роль |
| --- | --- |
| `scripts/build-standard-terms-snapshot.mjs` | поиск актов на actual.pravo.gov.ru и сборка снимка |
| `src/Csms.Infrastructure/Seeds/standard-contract-terms.json` | 4 акта с полным текстом актуальной редакции и SHA-256 |
| `GET /api/standard-contract-terms/catalog` | выдача каталога (PARAM `governmentOnly=true` — только ПП РФ) |
| `GET /api/standard-contract-terms/{code}` | один акт |
| `GET /api/standard-contract-terms/{code}/pdf` | скомпонованный PDF карточки ЕИС |
| `POST /api/standard-contract-terms/refresh` | явное обновление: pravo.gov.ru, при недоступности — ЕИС |
| `src/services/Npa/standardContractTerms.api.ts` | zod-контракт и React Query на фронте |

Состав на 27.11.2026 — 4 действующих акта, все приняты Правительством РФ:
ПП РФ от 23.12.2016 № 1466 (субподрядчики из СМП и СОНКО), от 19.08.2022
№ 1445 (регулярные перевозки), от 12.01.2023 № 10 (тест-полоски на глюкозу),
от 14.11.2024 № 1550 (авиационные работы для медицинской помощи). Утративший
силу ПП РФ от 02.07.2014 № 606 в каталог не входит. Поиск идёт по названию
(`AttrId 7`) с горизонтом с 1900 года: API актуальной редакции не умеет
полнотекстовый поиск, а акты «о типовом договоре» в других сферах не являются
типовыми условиями контракта 44-ФЗ и отбираются регулярным выражением.

Текст в снимок берётся дословно из `redtext` актуальной редакции pravo.gov.ru:
Word-HTML очищается от стилей и комментариев портала, но не редактируется по
смыслу. При старте сервис сверяет SHA-256 каждого текста, источник и связку
«всегда применяется → принято Правительством РФ». Обновление из сети делается
только `POST /refresh` — старт библиотеки остаётся офлайн-режимом.

Если pravo.gov.ru недоступен, обновление берёт карточки типовых контрактов с
`zakupki.gov.ru` и компонует их PDF-вложения (`Docnet.Core`) для скачивания.
Приложения ЕИС — сканы без текстового слоя, поэтому дословный текст остаётся из
снимка pravo.gov.ru: OCR без отдельного одобрения не применяется. В ответе это
отражено полями `textSource` (`pravo.gov.ru (снимок)`) и `pdfSha256`; карточка
показывает настоящий источник текста и ссылку на PDF ЕИС, а не выдаёт скан за
текст портала. Для актов без карточки ЕИС (например, ПП РФ № 1466) реквизиты и
ссылки остаются из снимка. Если не отвечают оба источника, каталог не меняется.

### Word и проект контракта

Тот же дословный снимок собирается в `.docx` без LLM и OCR:

| Файл | Роль |
| --- | --- |
| `src/services/Npa/standardContractTermsWord.ts` | разбор текста на блоки (шапка, раздел, пункт, подпункт), оглавление и сборка Word |
| `src/components/Npa/StandardTermsWordViewer.tsx` | встроенный просмотр Word-страницы с содержанием и подсветкой активного пункта |
| `src/components/Legal/NpaLibraryPage.tsx` | кнопки «Просмотр Word» и «Скачать Word» в каждой карточке типового условия |
| `src/components/ContractProject/StandardContractTermsPanel.tsx` | выбор акта в конструкторе проекта контракта, ссылки на источник и карточку, отдельная выгрузка Word |
| `src/services/ContractProject/contractProjectExport.ts` | выгрузка проекта контракта в Word вместе с выбранными условиями |

Парсер только расставляет абзацы и не меняет ни текст, ни официальную
нумерацию (включая добавочные номера вроде `24.1` и `4.1`). Пустые строки снимка
не переносятся в документ. В Word в футер и метаданные попадают `textSource`,
ссылка на редакцию и SHA-256 текста. Кнопка «Просмотр Word» есть у каждого
типового условия и в библиотеке, и в конструкторе проекта контракта: она открывает
модальное окно со страницей в стиле Word и постоянно доступным содержанием —
шапка, разделы, пункты и подпункты; активный пункт подсвечивается при прокрутке.
Просмотр и скачивание используют один и тот же разбор снимка. Выбранный акт сохраняется в проекте контракта
полем `standardTerm` вместе с хешем: предпросмотр, вложение извещения и выгрузка
используют один и тот же снимок. Регрессионная проверка
`npm run check:standard-terms` сверяет склейку блоков с текстом снимка и реально
собирает оба `.docx`.

## Пересборка

```bash
node scripts/consultant/build-npa-library.mjs
```

Скрипт не скачивает документы: он сверяет каталог, карточки, манифест загрузок
и индекс. Если у записи нет поля `files`, но файлы лежат на диске (так было у
ПП РФ № 1875), скрипт проверяет их напрямую. После загрузки новой редакции нужно
сначала обновить манифест (`node scripts/consultant/fetch-pravo.mjs sync`), затем
пересобрать каталог.

Если меняется конвертер, тексты можно пересобрать без сети из сохранённых `.doc`:
`node scripts/consultant/fetch-pravo.mjs reconvert`. Портал оборачивает добавочные
номера в `<span class="W9">…</span>` (статья 276.1, часть 4.1, пункт 4.1)); раньше
теги просто снимались и получались несуществующие номера «2761», «41». Сейчас
точка восстанавливается до очистки разметки, и для `.txt`, и для `.md`. После
переконвертирования нужно переиндексировать консультант
(`POST http://127.0.0.1:5098/api/consultant/reindex`) и пересобрать каталог.
Семь записей, скачанных с publication.pravo.gov.ru, не имеют `.doc`-источника и
остаются в OCR-варианте: их numbering сверяется с первоисточником вручную.

## Просмотр

Ссылка документа имеет вид
`/consultant?doc=/api/consultant/source/npa/<slug>?format=md&title=…`.
Параметр `doc` — полный URL локального источника: его проверяет
`isLocalSource()` в `ConsultantPage.tsx`. Дополнительно можно передать `ref=ст. 34`
или `ref=ч. 6.1 ст. 34` — просмотр сразу прокрутит к нужной норме. Формат
`format=doc&download=1` отдаёт Word-совместимую копию.

### Правила преобразования в карточку

Любой акт, включая типовое условие из csms-api, подаётся как структурированный
документ: текст дословный, официальные заголовки и номера всех уровней логически
выделены, навигация доступна всегда — от пункта/подпункта до главы/раздела и
редакций акта. Если есть карточка или текст на `pravo.gov.ru` (в том числе для
другого акта, на который ссылается норма), она доступна внешней ссылкой; если
адреса нет, показывается честный статус, а не выдуманная ссылка. Полный перечень
правил для агентов — `AGENTS.md`, раздел «Правила преобразования НПА в карточки».

## Акты без официальной карточки

`order-567`, `order-999`, `order-348`, `order-384`, `order-402`, `goskomstat-1`.
Они перечислены в `docs/legal/consultant-pravo-gaps.md`: на pravo.gov.ru карточек
нет, поэтому в библиотеке они помечены как недоступные, а консультант не может
их цитировать как первоисточник. Источник текстов — только pravo.gov.ru; тексты
из других мест в индекс не добавляются.
