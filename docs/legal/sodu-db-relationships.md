# Связи в базе СОДУ (Access)

Служебная заметка для ревизии Q&A и переноса логики Access в CSMS. Составлена 24.11.2026 по файлу `D:\Работа Наташа\База\СОДУ\СОДУ.accdb`.

## Как получена схема

- Через OLE DB (`Microsoft.ACE.OLEDB.16.0`, 32-битный PowerShell): `GetOleDbSchemaTable` для `Tables`, `Columns`, `Primary_Keys`, `Foreign_Keys`.
- `MSysRelationships` недоступен без прав администратора базы, поэтому пользовательские связи взяты из `Foreign_Keys`.
- Полная выгрузка — `.tmp/consultant/sodu-schema.json` (не коммитится): **96 объектов** (83 `TABLE` + 13 `VIEW`), **94 первичных ключа**, **11 внешних ключей**.

## Связи из SQL пользователя

SQL: `Заключение контракта RIGHT JOIN Документация для УУ ON …Номер извещения…`.

- В Access `A RIGHT JOIN B` сохраняет все строки правой таблицы, то есть это `Документация для УУ LEFT JOIN Заключение контракта`. Направление обратно FK, но пара та же (FK № 3).
- Связь по «Уникальный номер позиции …» тоже оформлена — FK № 9, с отличием в написании.
- **Не оформлена FK связь по ИКЗ:**
  - `Документация для УУ.Идентификационный код закупки` (PK) ↔ `Заключение контракта.ИКЗ`;
  - `Документация для УУ.Идентификационный код закупки` ↔ `Сведения по позициям ПГ.Идентификационный код закупки`;
  - `Документация для УУ.Идентификационный код закупки` ↔ `КБК.ИКЗ закупки`, `КБК для извещений.ИКЗ закупки`, `Этапы контракта в извещении.ИКЗ закупки`, `Объекты закупок.ИКЗ закупки`, `Приказ о проведении закупки.ИКЗ`, `Сведения для принятия БО.ИКЗ`;
  - `Заключение контракта.ИКЗ` ↔ `Реестр контрактов.Идентификационный код закупки контракта` — FK № 4 есть, но родитель не PK.
- Не оформлены FK для текущих справочников способов/подспособов — связь только по совпадению значений.

Логическая цепочка для миграции:

`ПГ (Уникальный номер позиции) ← Документация для УУ → (Номер извещения) Заключение контракта → (ИКЗ) Реестр контрактов`, плюс параллельная связь по ИКЗ между `Документация для УУ` ↔ `Заключение контракта` ↔ позиция ПГ ↔ КБК/этапы/объекты.

## Рекомендации

1. Добавить к каждой паре явную привязку `таблица.поле` — сейчас в `source` только VBA-процедуры.
2. Завести словарь синонимов: `ИКЗ` / `Идентификационный код закупки` / `Идентификационный код закупки контракта`; варианты «Уникальный номер позиции…»; «Способ определения поставщика (подрядчика, исполнителя)» / «Способ определения поставщика».
3. явно зафиксировать недостающие логические связи (Документация.ИКЗ ↔ Заключение.ИКЗ ↔ ПГ ↔ КБК/этапы/объекты, текущие справочники способов); при необходимости добавить уникальный индекс по `Заключение контракта.ИКЗ`.
4. Не использовать `Внесение сведений по процедуре закупки` как канонический источник.
5. Заменить связь «по наименованию поставщика» на ИНН.
6. Вынести магические константы VBA (10/15/20/30 дней, 25%, 30%, 1,5×, коды КТРУ, сдвиги пунктов −6/−7) в параметры/справочники.
