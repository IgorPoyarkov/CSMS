# Офлайн-агент ООЗ по ГОСТ и НПА

## Зачем

Редактору ООЗ нужны подсказки не только по ГОСТу, но и по нормативным
правовым актам (ст. 33 44-ФЗ, ТР ТС, законы из карточек КТРУ). Агент не
генерирует текст и не ходит в сеть: он собирает предложения только из
зафиксированных локальных снимков и показывает дословную цитату рядом с
кнопкой подстановки.

## Источники

- `docs/snapshots/gost/okpd2-selection.json` — документы по ОКПД2 позиций
  плана-графика: `selected` (ГОСТы) и `otherStandards` (ТР ТС, законы).
- `public/gost/requirements.json` — требования из полного текста ГОСТов;
  каждое значение уже сопровождается проверенной цитатой.
- `public/gost/catalog.json` — карточки новых ГОСТов с protect.gost.ru.
- `docs/snapshots/civil-code-snapshot.json` — ст. 33 44-ФЗ, откуда берутся
  цитаты о составе описания закупки (п. 3 ч. 1 ст. 33).

Принцип `snapshot-first / offline-by-default` (`docs/tasks/snapshot-first-offline.md`):
агент не вызывает ЕИС, pravo.gov.ru или локальную LLM при открытии редактора.

## Сборка

```powershell
npm run build:ooz-agent
# или: node scripts/build-ooz-agent.mjs
```

Результат — `public/gost/ooz-agent.json` с версией, списком документов,
подсказками и привязкой документов к кодам ОКПД2 (`byOkpd2`). Версия меняется,
только когда меняется содержимое снимка. Текущая версия —
`ooz-agent-20261127-ff9bb8684f50` (3 документа, 17 подсказок).

## Правила

1. **Дословная цитата обязательна.** Значение попадает в подсказку, только если
   цитата есть в исходном снимке ГОСТа или НПА. Проверка —
   `scripts/check-ooz-agent.ts` (33/33) и `scripts/tests/ooz-agent.test.mjs`.
2. **Анти-галлюцинационные статусы.** Требования ГОСТа уже проверены
   `build-gost-requirements.mjs` по полному тексту: `status: confirmed`,
   `confidence: 1`. Подсказки по ст. 33 44-ФЗ используют дословную цитату, но
   сопоставление нормы с полем ООЗ делает человек: `status: needs_review`,
   `confidence: 0.55`. В редакторе такие подсказки помечены «требует проверки».
3. **Нет текста — нет значения.** У `ТР ТС 018/2011` и `220-ФЗ` в снимке только
   название из карточки КТРУ: они показываются со статусом `needs_full_text`,
   но поля не заполняются. Выдумывать требования по одному названию нельзя.
4. **Нормы ст. 33 показываются всегда**, даже когда по текущему ОКПД2 нет
   ГОСТа; требования ГОСТа — только для документов этого кода.
5. **Подстановка идемпотентна.** Повторное нажатие кнопки не дублирует текст;
   уже отмеченные компоненты описания из списка подсказок исчезают.
6. `GOST_NOT_MODERN` не зависит от агента: предупреждение по-прежнему
   вычисляется из обозначения ГОСТа и порога 2010 года.

## Проверки

```powershell
npm run check:gost   # включает check-ooz-agent.ts и тесты агента
npm test             # весь контур, включая check:gost
```

## Ограничения

- Агент пока детерминированный: он не анализирует произвольный текст ООЗ и не
  отвечает на вопросы пользователя. Для LLM-контура можно переиспользовать
  `scripts/consultant/` (RAG с цитатами) и анти-галлюцинационные проверки из
  `csms-api/src/Csms.Infrastructure/Npa/NpaLlmResponseParser.cs`.
- Статус `needs_review` означает ручную проверку в редакторе; отдельного
  `POST .../verify` у локального агента нет — такие endpoint есть только в
  csms-api (`/api/npa/.../verify`, `/api/documents/functions/{id}/verify`).
- Полного текста ТР ТС и законов в локальных снимках нет; allgosts.ru хранит
  только ГОСТы, поэтому для них нужен отдельный источник (например, снимок
  официальной страницы), а не браузерная выгрузка allgosts.ru.
- Документы подобраны по текущим планам-графикам: для другого ОКПД2 агент
  покажет пустой список, пока не будет пересобран `okpd2-selection.json`.
