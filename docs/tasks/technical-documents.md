# Локальный парсер технических документов (ГОСТ, СП, ТУ)

## Зачем

Редактору ООЗ нужны не только название ГОСТа из карточки, но и требования
из полного текста: гарантийный срок, гарантия на оборудование, монтаж,
тара и упаковка. Полный текст на protect.gost.ru — набор изображений и только
после входа, поэтому для текста используется browser-выгрузка HTML-страниц
allgosts.ru. Мониторинг **новых** ГОСТов по-прежнему идёт с protect.gost.ru
(`docs/tasks/gost-monitor.md`); allgosts.ru не заменяет этот источник.

`robots.txt` allgosts.ru разрешает обычные HTML-страницы и запрещает
`/*search`, `/*.pdf`, `/*.doc`, `/*.docx`. Скачивать файлы не нужно: полный
текст лежит в `<article>` страницы.

## Отбор по ОКПД2 плана-графика

Все 98 новых ГОСТов массово не выгружаются. Сначала определяется список
документов, которые реально нужны позициям ПГ:

```powershell
node scripts/select-gosts-by-okpd2.mjs
```

Скрипт собирает коды ОКПД2 из всех позиций всех планов (pg-адаптер `:3002`),
затем по ним находит карточки КТРУ в csms-api (`:5099`) и берёт ГОСТы из
`payloadJson.standards[]`. Результат — `docs/snapshots/gost/okpd2-selection.json`
всех найденных обозначений (их может быть несколько на один ОКПД2), с кодами
ОКПД2 и КТРУ. По состоянию на 2026-11-27: 2 плана, 179 позиций, 29 кодов
ОКПД2, 740 карточек КТРУ → 1 уникальный ГОСТ 30593-2015 для ОКПД2
49.31.21.110 (остальные стандарты в карточках — законы и ТР ТС).

Ссылку на страницу документа ищут **в браузере** через форму `/search` сайта
(Node-запросы к `/search` по `robots.txt` не делаются). Найденный URL добавляется
в `sources.json`, после чего текст выгружается по описанию ниже. Выгруженные
сейчас тексты: ГОСТ 1232-2017 (первый образец) и ГОСТ 30593-2015 (по ОКПД2 ПГ).

## Как выгружать документ

1. Открыть страницу документа в браузере (например,
   `https://allgosts.ru/29/080/gost_1232-2017`).
2. В консоли разработчика выполнить `scripts/browser/export-article.js`.
   Скрипт скачает `<designation>.html` и `<designation>.txt` — разметку и
   видимый текст `<article>`.
3. Положить файлы в `docs/snapshots/gost/fulltext/`.
4. Добавить соответствие `обозначение → URL страницы` в
   `docs/snapshots/gost/fulltext/sources.json`.
5. Пересобрать снимок требований:

   ```powershell
   node scripts/build-gost-requirements.mjs
   ```

Node-`fetch` на allgosts.ru отдаёт страницу проверки «подтвердите, что вы не
робот», поэтому обход капчи в скриптах сознательно не делается: текст
выгружается человеком через браузер, а в репозиторий попадает уже снимок.

## Устройство парсера

- `scripts/lib/allgosts.mjs` — чистые функции без сети: `decodeHtml`,
  `warrantyMonths` («пять лет» → 60), `parseSections` (HTML → разделы по
  `<h2>/<h3>`), `parseGostText` (txt → разделы по номерам пунктов),
  `extractGostRequirements`.
- `scripts/lib/tech-doc.mjs` — единая точка входа `parseTechnicalDocument()`
  и реестр `TECH_DOC_SOURCES`. Для нового сайта добавляется источник в реестр
  и, если у него другая разметка, парсер рядом с `allgosts.mjs` плюс ветвление
  в `parseTechnicalDocument()`.
- `scripts/build-gost-requirements.mjs` — собирает `public/gost/requirements.json`
  из всех файлов каталога снимков; `.html` предпочтительнее `.txt`, так как
  сохраняет структуру разделов.
- `scripts/tests/tech-doc.test.mjs` — тесты парсера и извлечения требований.

**Правило цитаты:** значение попадает в снимок, только если дословная цитата
есть в тексте документа. Ссылки на другие ГОСТы, определения и требования
к методам испытаний не подставляются как требования к товару. Упоминание
«маркировок ТС» в перечне документации тоже не считается требованием к упаковке.
Если подходящей цитаты нет, поле просто не предлагается — выдумывать значение
нельзя: например, в ГОСТ 30593-2015 подходящих цитат нет, поэтому он хранится
в снимке с пустым списком требований.

## Потребители

- `src/services/GostRef/gostRequirements.schema.ts` — zod-контракт снимка,
  `findGostRequirements()`.
- `src/services/GostRef/gostRef.api.ts` — `useGostRequirements()`, query key
  `["gostRequirements"]`, читает статический `/gost/requirements.json`.
- `ObjectDescriptionEditor` — в карточке ГОСТа под подсказкой показываются
  кнопки «Подставить: …» с цитатой. Подстановка идемпотентна: повторное
  нажатие не дублирует текст, «Упаковка» добавляется в состав описания
  один раз. Все изменения остаются черновиком до сохранения ООЗ.

`GOST_NOT_MODERN` не зависит от полного текста: как и раньше, это `warning`,
год берётся из обозначения, порог — 2010.

## Проверки

```powershell
npm run check:gost   # регрессии ГОСТа + tech-doc-тесты
npm test             # вся проверка, включая снимок требований
```

`check-ooz-gost-catalog.ts` дополнительно сверяет, что каждая цитата из
`requirements.json` дословно присутствует в сохранённом тексте документа.
