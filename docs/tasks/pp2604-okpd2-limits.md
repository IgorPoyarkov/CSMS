# ПП РФ № 2604: ОКПД2 → предельные величины значимости критериев оценки

## Источник и способ получения

Текст взят **из государственного API официального опубликования**, а не с
производных сайтов:

- `GET http://publication.pravo.gov.ru/api/Documents?Block=government&Number=2604&NumberSearchType=0&PageSize=30`
  → `eoNumber = 0001202201040005`, 32 страницы;
- `GET http://publication.pravo.gov.ru/file/pdf?eoNumber=0001202201040005`
  → подписанный скан PDF (1 516 701 байт);
- приложение № 2 «Предельные величины значимости критериев оценки заявок»
  находится на **стр. 27–29 PDF** (страницы повёрнуты на 90°, распознаны
  после поворота; в проекте для этого используется Docnet + Tesseract rus);
- справочник кодов — активная версия НСИ ЕИС `nsiOKPD2`
  (`eis-nsiOKPD2-7c7ee4215e3ee405`, 21 066 кодов, SourceDocument:
  «Официальный сайт ЕИС zakupki.gov.ru, публичное дерево НСИ»).

**Ключевой факт:** в приложении № 2 **нет ни одного кода ОКПД2**. Там 20
наименований объектов закупки и три числа на строку. Поэтому любая связь
«код ОКПД2 → позиция приложения» является *производной* и обязана нести
источник. Три типа связи (`basis` в коде):

| `basis` | Что означает |
| --- | --- |
| `classifier` | наименование кода из НСИ ЕИС совпадает/уточняет наименование позиции приложения |
| `purpose` | позиция определяется целью закупки, а не кодом (поз. 13) |
| `residual` | остаточный случай «работы, услуги» (поз. 2) |

⚠️ Правила `ref.npa_rules` агента НПА для `pp-2604` **не являются источником**
этих пределов: там материализованные `include`-правила на весь справочник
ОКПД2 без привязки к позициям приложения № 2.

## Соответствия и предельные величины

Цена = минимальная значимость критерия «цена контракта», расходы =
максимальная значимость критерия «расходы», нестоимостные = максимальная
сумма значимости критериев «характеристики» + «квалификация». Прочерк —
критерий «расходы» для позиции не применяется.

## Правила валидации (реализованы в `bidEvaluation.schema.ts`)

1. **Код отсутствует** (`okpd2Codes` пуст) — информационное предупреждение:
   категорию и пределы нельзя проверить автоматически, нужна ручная выборка
   категории из приложения № 2. Ошибкой не считается: код может быть ещё не
   заполнен на черновике.
2. **Некорректный формат кода** — ошибка с указанием кода: ожидается
   `\d{2}(\.\d{1,3}){0,3}` после нормализации (`,` → `.`, пробелы убираются).
   Наличие кода в активном справочнике НСИ проверяется отдельно при импорте.
3. **Выбор правила** — `purpose` → самый длинный префикс → `residual`.
   Каждая строка `matches` возвращает `category`, `row`, `basis`, `source`
   (акт + поз. + код/наименование ОКПД2) и `needsReview`.
4. **Неоднозначная связь** (`needsReview`) — предупреждение с причиной и
   источником; не блокирует сохранение, но требует подтверждения человеком.
5. **Разные категории в одной закупке** (`conflict`) — предупреждение с
   перечнем «код → поз. → источник»; категория выбирается вручную.
6. **Несоответствие выбранной категории** — ошибка с номером позиции и
   источником связи.
7. **Проверка пределов** для выбранной категории — цена ≥ минимума, расходы
   ≤ максимума (если применимо), сумма нестоимостных критериев ≤ максимума;
   все сообщения ссылаются на номер позиции приложения № 2.
8. **Вид процедуры** — при `tender` дополнительно проверяется аукционный
   перечень РП РФ № 471-р (ч. 6 ст. 24 44-ФЗ); это отдельный акт, а не
   приложение № 2.

Smoke-проверка этих правил (источник, длина префикса, формат кода, цель
закупки, конфликт и сообщения валидации) запускается командой
`npm run check:pp2604` (`scripts/check-pp2604-rules.ts`).

## Случаи, когда код отсутствует или отнесение неоднозначно

| Ситуация | Поведение |
| --- | --- |
| Код ОКПД2 не заполнен | предупреждение, ручной выбор категории |
| Код невалиден/не в НСИ | ошибка формата; дальнейшая проверка категории невозможна |
| 10, 11 без цели закупки | поз. 1 + `needsReview`; нужно указать `okpd2Purpose = food_for_social_orgs` для поз. 13 |
| 85.4 | поз. 15 приблизительно, `needsReview`; отдельного кода «отдых детей» нет |
| 91.01 / 91.02 / 91.03, 71.11.23 | поз. 6–8, `needsReview`: музей/архив/историческое место ≠ обязательно реставрация |
| 43.3 против остальных 43 | поз. 5 против поз. 3 — уточнять вид работ |
| 42.11 против остальных 42/43 | поз. 4 против поз. 3 — автодорога против иного строительства |
| 62, 63; 80; 90; 59.1; 69.2; 71.2 | `needsReview`: коды шире соответствующих позиций приложения |
| Несколько позиций СЗ с разными категориями | `conflict`, выбор категории человеком |
| Объект закупки одновременно товар и услуга | категория определяется по преобладающему предмету контракта; при спорных кодах — ручная проверка |
