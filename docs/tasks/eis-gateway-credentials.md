# Задача: ввод и хранение учётных данных заказчика для альтернативной интеграции ЕИС

Статус: **заготовка задачи**, реализация после получения WSDL/ТФФ и тестового
контура. Связана с `docs/tasks/eis-alternative-integration.md` (общий план) и
пакетом A2 в `docs/tasks/eis-chain-readiness.md`.

## Цель

Администратор организации должен один раз ввести технические логин/пароль,
выданные в личном кабинете ЕИС для альтернативной интеграции, видеть срок их
действия и текущий статус, проверять соединение по явной кнопке — и никогда не
видеть сохранённый пароль снова.

## Границы

- Изменения только в настройках организации/шлюза. Доменные сущности,
  кириллические колонки БД и парсинг открытых данных не трогаются.
- Хранение и API — в соседнем репозитории `csms-api`; форма — в этом репозитории.
- Шлюз по умолчанию выключен: `EisGateway__Enabled=false`, `Transport=mock`.
  Наличие сохранённых учётных данных само по себе не включает отправку.

## Данные одной записи (профиль заказчика)

| Поле | Назначение |
|---|---|
| `id`, `organizationId` | привязка к своей организации |
| `login` | технический логин из ЛК ЕИС |
| `passwordEncrypted` | зашифрованный пароль; в ответах API не отдаётся |
| `issuedAt`, `expiresAt` | дата выдачи и окончания срока действия |
| `ownerName` | ФИО сотрудника, от чьего имени выдана пара |
| `status` | `NotConfigured` / `Active` / `ExpiringSoon` / `Expired` / `Invalid` |
| `lastVerifiedAt`, `lastError` | результат последней явной проверки (без секретов) |
| `createdAt`, `updatedAt` | аудит |

## Контракт API (csms-api)

| Метод | Путь | Правило |
|---|---|---|
| `GET` | `/api/eis/gateway/credentials?organizationId=…` | пароль только маской `••••••••` |
| `POST` | `/api/eis/gateway/credentials` | сохранить новую пару |
| `PUT` | `/api/eis/gateway/credentials/{id}` | ротация; пустое поле пароля = оставить прежний |
| `DELETE` | `/api/eis/gateway/credentials/{id}` | отозвать пару |
| `POST` | `/api/eis/gateway/credentials/{id}/verify` | явная проверка соединения |

- Доступ: только администратор организации.
- Каждая операция пишется в журнал аудита (кто, когда, какое действие); текста
  пароля в журнале нет.
- `verify` вызывается только по кнопке, с ограничением частоты; фоновых проверок
  нет. Ошибка возвращается текстом без логина и пароля.

## Безопасность

- Шифрование при хранении: мастер-ключ/KMS вне репозитория; на разработке —
  DPAPI / User Secrets. В `appsettings.json` и в git секретов нет.
- Пароль не попадает в ответы API, логи, сообщения об ошибках и уведомления.
- Напоминание о ротации за 30 дней до `expiresAt`, бейдж в интерфейсе.
- Просроченная или неверная пара блокирует отправку с понятным сообщением.

## Интерфейс

Раздел «Альтернативная интеграция ЕИС» в настройках организации:

- поля: организация (только для чтения), технический логин, пароль
  (`type="password"`, переключатель показа), дата выдачи, дата окончания,
  ФИО сотрудника;
- действия: Сохранить, Проверить соединение, Ротация, Отозвать (с подтверждением);
- бейдж статуса: «Не настроено» / «Активно» / «Истекает через N дней» /
  «Срок истёк» / «Не прошло проверку».

## Порядок работ

1. `csms-api`: сущность, миграция, шифрование, эндпоинты, аудит, права.
2. Фронт: zod-схема, API-клиент, форма, бейдж статуса и подтверждение отзыва.
3. Связать профиль с отправителем `scripts/lib/eis-gateway.mjs`: учётные данные
   берутся из профиля организации, а не из глобального окружения.
4. Тесты: маскировка, шифрование/расшифрование, расчёт статуса по дате,
   проверка прав, валидация формы.

## Definition of done

- Администратор может сохранить, ротировать и отозвать пару; ответ API не
  содержит пароль в открытом виде.
- Просроченная пара не допускает отправки и показывает понятную причину.
- Проверка соединения запускается только по кнопке и не пишет секреты в логи.
- Офлайн-старт не меняется: без `EisGateway__Enabled=true` сеть не вызывается.

## Зависимости

WSDL/ТФФ конкретной версии интерфейса, тестовый контур ЕИС, выбранный способ
ГОСТ-TLS (локальный агент или туннель), решение о хранилище ключа.
