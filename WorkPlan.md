# Стратегия парсинга: snapshot-first / offline-by-default (согласовано 2026-11-22)

**Решение пользователя.** Стартуем без взаимодействия с ЕИС. Главное на
первом этапе — помощь в документах к извещению, СЗ и проекту контракта по
данным открытого доступа. Сервер, сертификаты и лицензии информационной
системы подключаем позже, если спрос окупает владение; при этом меняется
только шаг получения данных, а не парсеры, DTO и шаблоны документов.

**Принцип.** Разделить контур на независимые шаги:

```
fetch (сеть, опционально)
  → snapshot (неизменяемый каталог + манифест: источник, дата, SHA-256)
    → parse (чистая функция без сети)
      → projection (единая read-side модель)
        → publish (API / DOCX / PDF / UI)
```

В офлайн-режиме `fetch` не вызывается: берём готовый снимок. Полный план и
фактический инвентарь снимков (версии, количества, хеши, источники) зафиксированы
в `docs/tasks/snapshot-first-offline.md` и `docs/snapshots/manifest.json`.

**Почему так.** Сейчас логика разбросана по трём репозиториям и трём режимам
(SOAP ЕИС, публичный сайт, ручные скрипты), а большая часть сложности — не
бизнес-правила, а нестабильность сети: 429, токены, ГОСТ-TLS, незавершённые
обходы. Один раз скачанный и подписанный хешем снимок снимает эту сложность с
основного сценария и делает результат воспроизводимым.

**Фаза 0 (выполнено).** `npm start` и `npm run api` по умолчанию не поднимают
фоновые агенты, которые сами ходят в ЕИС и на портал публикации НПА
(`Npa__Enabled=false`, `EisSchemas__Update__Enabled=false`,
`EisCounterparties__Update__Enabled=false`). Ручные эндпоинты обновления и
внешние переменные окружения остаются приоритетными. Уже опубликованные
версии справочников и правил продолжают отдаваться локально. Потеря
`payloadXml` при повторной подписи пакета проверена: исправление уже в коде —
настоящий XML не пересобирается в заглушку.

**Фаза 1 (впереди).** Канонические DTO (`PurchasePlanItem`, `Notice`,
`Contract`, `AcceptanceAct`, `Payment`, `NpaRule`) и адаптеры: XML ЕИС, HTML
публичной карточки, XLSX/CSV, `db.json`. Фронт не парсит XML сам. Один
HTTP-клиент zakupki.gov.ru с 429-policy и resume, контент-адресное хранилище
raw по SHA-256, мастер «Импорт из открытых данных» по ИНН/реестровому номеру.
В документах — пометка «Источник: открытый доступ ЕИС, снимок от …».

**Фаза 2 (впереди).** `XmlReader` вместо загрузки всего `export.xml` в память,

почти одинаковых парсеров, перф-тесты на 1000 контрактов.

**Фаза 3 (по спросу).** ЕИС-шлюз за явным флагом, токен ЕСИА, ГОСТ-TLS,
сервер и лицензии. Расчёт стоимости владения — до решения о сервере.

read-side DTO (`ContractCardViewDto` как образец). Текущий ЕИС-парсер
оставляем основным и добавляем новые парсеры рядом, а не вместо него.
